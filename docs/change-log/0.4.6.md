# 0.4.6 (July 25, 2026)

`0.4.6` hardens the boundary between recovery semantics in `agora-etl` and the
official backend bundle. It is a coordinated core release: use it with
`agora-etl-plugins>=0.4.3,<1`.

## Recovery identity and policy preflight

- Checkpoint-capable CSV, JSONL, and Parquet sources now persist a stable
  `SourceIdentity`. Resume fails closed when the configured source no longer
  matches; an operator can explicitly choose reset or allow behavior.
- Delivery capabilities and policy mismatch diagnostics are available before a
  pipeline starts. This prevents a replay-safe claim from silently proceeding
  with a source/sink combination that cannot support it.
- Failure decisions now provide a common classification, retryability, DLQ
  eligibility, and alert severity envelope for core and official plugins.
- Generic PostgreSQL upserts and Redis `SET` writes now remain replay-unsafe by
  default: an application must explicitly attest to a stable conflict/key
  contract before `DeliveryPolicy(require_replay_safe=True)` can accept them.

## Release compatibility

`SourceIdentity` is a public core contract consumed by the official BigQuery,
Kafka, PostgreSQL, Redis, and S3 plugins. Therefore `agora-etl-plugins 0.4.3`
requires `agora-etl>=0.4.6,<1`; it must not be installed with the previously
published `0.4.5` artifact.

## Upgrade

Upgrade core and plugins together:

```bash
pip install --upgrade "agora-etl>=0.4.6,<1" "agora-etl-plugins>=0.4.3,<1"
```

Existing checkpoints that lack source identity are treated as a mismatch by
default. Inspect the source and choose an explicit reset or allow policy only
after validating that replay is safe for the destination.
